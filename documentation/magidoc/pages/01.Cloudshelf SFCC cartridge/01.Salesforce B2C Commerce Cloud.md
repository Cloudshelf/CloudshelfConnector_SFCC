# Summary

This document provides general overview and technical instruction of
installing of Salesforce Commerce Cloud (SFCC) LINK cartridge that lets
you integrate Cloudhshelf with SFCC.

# Overview

Cloudshelf cartridge (int_cloudshelf) for Salesforce B2C Commerce Cloud.

Cartridge allows to connect SFCC instance with Cloudshelf and includes
the next functionalities:

-   Export products and catalogs from SFCC to Cloudshelf

-   Export stores from SFCC to Cloudshelf

-   Order management (aka transfer of basket from Cloudshelf to SFCC)

-   Update order status on Cloudshelf

The cartridge can be used by any new or existing SFCC retailer to be
able to connect to Cloudshelf after simply installing the cartridge.

# Compatibility

Cartridge is compatible with 6.3.0 and 7.0.0 SFRA version and Salesforce Commerce
Cloud API version 24.1 (Compatibility Mode: 22.7)

# Implementation Guide

## Prerequisites

Before installing cartridge on SFCC side make sure you have:

-   Account and API key created on Cloudshelf side - [Getting Started](https://documentation.cloudshelf.ai/getting-started/welcome)

-   SFCC instance with setup site and product catalog

-   SFCC business user account

## Installing cartridge

Complete the following steps to install the cartridge.

### Initial Install

Clone [repository](https://github.com/Cloudshelf/CloudshelfConnector_SFCC) to your computer.

Upload int_cloudshelf cartridge to your SFCC instance.

See the SFCC documentation for adding a cartridge to your storefront:

-   [Upload Code for SFRA](https://developer.salesforce.com/docs/commerce/sfra/guide/b2c-build-sfra.html#upload-code-for-sfra)

Cartridge does not contain any additional npm dependencies or client js
script changes and can be simply uploaded to SFCC instance after
receiving a copy of it.

### Registering the Cartridge with Individual SFCC Sites 

1.  Navigate to **BM > Administration > Sites > Manage Sites > [SiteName] > Settings tab**.

2.  Add ":int_cloudshelf" to the effective cartridge path.

3.  Click "Apply".

## Setup

Configuring custom Site Preferences for Cloudshelf API key value is
required. All other settings are optional.

### Configuring Custom Site Preferences for API key

Complete the following steps.

1.  Navigate to **Site > (select desired SFCC Site) > Site Preferences > Custom Preferences > Cloudshelf**

2.  Select the appropriate Instance (Sandbox/Development, Staging,
    Production), and click Apply.

3.  Set the following using the value provided by your Cloudshelf
    representative: Cloudshelf API Key

4.  Click Apply.

### Custom Site Preferences Configurations

Other setting available in **Navigate to Site > (select desired SFCC
Site) > Site Preferences > Custom Preferences > Cloudshelf**

| Id | Name      | Description |
|----|-----------|-------------|
| cloudshelfProductMetadataMapping | Product Metadata Mapping     | JSON mapping of product attributes to [cloudshelf product metadata properties](https://documentation.cloudshelf.ai/types/Product). Key represents SFCC attribute, value cloudshelf key. Custom attribute must be specified with custom. prefix e.g. - *{"custom.size": "size", "custom.badge": "symbol"}* |
| cloudshelfCategoryMetadataMapping   | Category Metadata Mapping | JSON mapping of category attributes to [cloudshelf product group metadata properties](https://documentation.cloudshelf.ai/types/ProductGroup). Key represents SFCC attribute, value cloudshelf key. Custom attribute must be specified with custom. prefix e.g. - *{"custom.size": "size", "custom.badge": "symbol"}*
| cloudshelfStockLevelsToken | Stock Levels Token | Turns on [live stock levels](#live-stock-levels). Cloudshelf displays have to send this value to read stock from SFCC. Leave empty to keep live stock off. |
| cloudshelfStoreMetadataMapping   | Store Metadata Mapping | JSON mapping of store attributes to [cloudshelf location metadata properties](https://documentation.cloudshelf.ai/types/Location). Key represents SFCC attribute, value cloudshelf key. Custom attribute must be specified with custom. prefix e.g. - *{"phone": "mobile", "custom.badge": "symbol"}*

## Jobs & Schedule

In BM go to **Administration > Operations > Jobs**.

Two jobs are part of the initial cartridge setup

-   **CloudshelfDataExportFull** -- Full export of SFCC products and
    categories to cloudshelf. Also, exports SFCC stores marked with
    isCloudshelf flag to Cloudshelf system as locations

-   **CloudshelfDataExportDelta** -- Delta export of products data to
    Cloudshelf

For initial full products export simply click "Run" button of
CloudshelfDataExportFull job. It will exports all sites products and
categories to cloudshelf and create default theme and cloudshelf
entities in cloudshelf system.

A full export also removes from Cloudshelf the products, variations and categories it no longer finds in
SFCC, for example products or categories that were deleted or taken offline. Only what came from this
cartridge is removed. A category that is still online in SFCC is kept even when it has no products; if
Cloudshelf still holds products for it, they are cleared from the category. Removing a category leaves
its products in Cloudshelf, and also removes any tile that shows the category on a Cloudshelf. This is
controlled by the **removeMissing** parameter of the ProductExport step of the
CloudshelfDataExportFull job:

-   **ON** (default) - remove them, unless more than half of the products in Cloudshelf would be removed.
    That usually means the search index was empty or being rebuilt when the export ran, so nothing is
    removed and an error is logged. The same limit applies to categories: when more than half of them
    would be removed, none are, and when more than half of the categories that hold products would be
    emptied, none are.

-   **OFF** - never remove anything.

-   **NO_LIMIT** - remove them however many there are. Use it for one run when a large part of the
    catalog really has been retired.

Nothing is removed when the export stops on an error before it has read the whole catalog. The
`custom-cloudshelf` log lists every product, variation and category that is removed.

To export stores from SFCC to Cloudshelf as location go to **BM > Merchant Tools > Online Marketing > Stores > [select store] > CLOUDSHELF Tab**, set isCloudShelf to be "Yes" and click "Save"

To change jobs configs in BM go to **Administration > Operations > Jobs > select a specific job**

-   In Schedule and History tab you can configure triggering interval
    for the job

-   In Job Steps tab you can select specific sites for which export
    should work

-   In Job Steps tab by selecting ProductExport step you can configure
    export mode (FULL or Delta)

## Starting a sync from Cloudshelf

The jobs can also be started from the Cloudshelf Manager, with the same sync buttons other
platforms use. A full sync starts **CloudshelfDataExportFull** and a partial sync starts
**CloudshelfDataExportDelta**, so keep those two job IDs as they are imported. Scheduled runs
and runs started in BM keep working as before.

Cloudshelf starts the jobs through the Salesforce Commerce API, so it needs an API client that
is allowed to run jobs on your instance. Set it up once:

1.  In BM go to **Administration > Site Development > Salesforce Commerce API Settings** and
    note the **Short Code** and the **Organization ID** (for example `f_ecom_zzxy_prd`).

2.  In Account Manager (<https://account.demandware.com>) go to **API Client > Add API Client**
    and fill in:

    -   **Display Name** - for example "Cloudshelf sync" (40 characters at most).

    -   **Password** and **Confirm Password** - this is the client secret. Keep it, it is not
        shown again.

    -   **Organizations** - your organization.

    -   **Roles** - click **Add** and select **Salesforce Commerce API**. The role then shows
        "No role scope defined": click the button on the role's row and select the instance
        whose jobs Cloudshelf should start.

    -   **Default Scopes** and **Allowed Scopes** - `sfcc.jobs.rw`

    -   **Token Endpoint Auth Method** - `client_secret_basic`

    Click **Save** and copy the new **API Client ID** from the list of API clients.

3.  In the Cloudshelf Manager open the Organization settings and fill in the **Salesforce sync**
    section: **Short Code**, **Tenant ID** (the Organization ID from step 1, with or without
    the `f_ecom_` prefix), **API Client ID** and **API Client Secret**. Save.

The sync buttons are available once all four fields are filled in. If Salesforce does not start
the job, the Cloudshelf Manager shows the reason, for example that the API client was not
accepted or that the job is already running.

Both jobs report their progress to Cloudshelf while they run, however they were started, so the
Cloudshelf Manager shows whether a sync is running, finished or failed. A status that cannot be
reported is written to the `custom-cloudshelf` log as a warning and does not stop the export.

## Live stock levels

Product exports tell Cloudshelf whether each variant is in stock at the time of the export. With live
stock levels turned on, a display also asks SFCC for the current stock each time a shopper opens a
product, shows it, and stops the purchase if the product has sold out since the last export.

The cartridge answers these requests at the `Cloudshelf-StockLevels` endpoint, in the format described in
[Real-Time Stock Levels](https://documentation.cloudshelf.ai/getting-started/real-time-stock-levels).

To turn it on:

1.  In BM go to **Site > (select desired SFCC Site) > Site Preferences > Custom Preferences > Cloudshelf**
    and set **Stock Levels Token** to a long random value of your choice. While it is empty the endpoint
    answers every request with "not found".

2.  In the Cloudshelf Manager go to **Organization** settings and set:

    -   **Stock Level URL** to
        `https://<your storefront host>/on/demandware.store/Sites-<SiteID>-Site/default/Cloudshelf-StockLevels`

    -   **Stock Level Auth Token** to the same value as the Stock Levels Token.

What a display is told about a variant:

-   **Online stock** - the quantity available to sell in the inventory list assigned to the site. This is
    what a shopper can order.

-   **Store stock** - for each store with isCloudShelf set to "Yes" and an inventory list assigned, the
    quantity available to sell in that store's inventory list. A display in that store can show it as
    stock available there.

-   A perpetual inventory record is reported as 9999 available.

Each request is written to the `custom-cloudshelf` log: the variant, the location asked about, what was
answered and how long it took. Refused requests are logged as warnings with the reason, for example a
missing or wrong token.

## Logs

The cartridge writes to three logs. Send the first one, and the second if you have it, when you ask
Cloudshelf for help with a sync.

| Log | Where | What it holds |
|---|---|---|
| Job log | `Logs/jobs/CloudshelfDataExportFull/` and `Logs/jobs/CloudshelfDataExportDelta/`, one file for each run. It is also linked from the run in **Administration > Operations > Jobs**. | Everything one run did: its summaries, every problem and how the run ended. |
| `custom-cloudshelf` | `Logs/custom-cloudshelf-*.log`, one file for each day | The same lines for every run of the day, and the lines of the storefront controllers. |
| `service-cloudshelf-graphql` | `Logs/service-cloudshelf-graphql-*.log`, one file for each day | One entry for every request to Cloudshelf: how long it took, what was sent and what Cloudshelf answered. |

What to look for in a job log:

-   **`Product export starting`** - the first line of the export, with the version of the cartridge
    that is running. The same version is sent to Cloudshelf with every request.
-   **`Product export summary`** - how many products and variations the run read and sent, and how
    many requests failed or were rejected.
-   **`Product export progress`** - written every 2,500 products while the export runs, with the
    same counts so far.
-   **Errors** - each one says what was being sent, with the first and last id, and why it failed.
    For example:

    ```
    Products not sent: chunk 28, 170 products, gid://external/salesforceProduct/A to
    gid://external/salesforceProduct/B. Reason: SERVICE_UNAVAILABLE, TIMEOUT,
    SocketTimeoutException:Read timed out
    ```

    A request that got no answer from Cloudshelf is sent once more before it counts as failed.
    When Cloudshelf answers with an error, the reason includes a `traceId`: quote it to Cloudshelf
    support.
-   **The recap** - when anything went wrong, the product export step ends with a warning that
    repeats the summary and lists the first 20 problems. The last screen of the step is then
    enough to see what happened.

What a failed request means for your data:

-   Products that were not sent are sent again by the next full export.
-   Variations that were not sent have their price and stock sent again by the next export, and
    everything else by the next full export.
-   A category whose products were not fully sent may show only part of its products until the next
    export that sends it.

Notes on what Salesforce writes:

-   Warnings and errors are always written. Summaries and progress are info lines. If they are
    missing from your logs, switch on **Info** for the instance in **Administration > Operations >
    Custom Log Settings**. They are few: a full export of 21,000 products in 44 categories writes
    about 90 lines, 19 KB.
-   Salesforce stops writing to a log file once it reaches 10 MB in a day. The cartridge keeps its
    logs short for that reason: the service log holds one line for a request and one for its
    answer, and the request and answer themselves are written, cut to 2,000 characters, only when
    something went wrong. With 21,000 products the service log grows by about 0.4 MB for a full
    export and 0.2 MB for a delta export.
-   If the service log still fills up, because the catalog is very large and the delta export runs
    often, switch off **Communication Log Enabled** for the `cloudshelf.http.graphql` service in
    **Administration > Operations > Services**. The job log and the `custom-cloudshelf` log do not
    depend on it.
-   For the full text of every answer from Cloudshelf, switch on **Debug** for the `graphql`
    log category on a sandbox. One export of a large catalog fills the log at that level, so
    switch it off again afterwards.

## Order management

Transferring basket from Cloudshelf to SFCC functionality works using
OCAPI as result the next are required: creating OCAPI client id and
setting up OCAPI configs in business manager.

More details about Shop OCAPI can be found by link - [Shop API](https://developer.salesforce.com/docs/commerce/b2c-commerce/references/ocapi-shop-api?meta=Summary)

General OCAPI documentation link - [Get Started With OCAPI](https://developer.salesforce.com/docs/commerce/b2c-commerce/references/b2c-commerce-ocapi/get-started-with-ocapi.html)

[OCAPI client and appropriate client
id](https://developer.salesforce.com/docs/commerce/b2c-commerce/references/b2c-commerce-ocapi/clientapplicationidentification.html)
can be created in [SFCC account
manager](https://account.demandware.com/dw/account/Home#!/) by account
manager administrator.

![](/328bb2ecb632c7b867850da2225ff83bd3f3278c.png)

OCAPI client permission and allowed origins for specific SFCC
organization or site can be setup in the SFCC business manager using
[OCAPI
setting](https://developer.salesforce.com/docs/commerce/b2c-commerce/references/b2c-commerce-ocapi/ocapisettings.html).

In BM go to **Administration > Site Development > Open Commerce API Settings > select required site context**
